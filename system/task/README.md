# Stewardship Task System

টাস্ক ট্র্যাকিং, রেজিস্ট্রি ও অডিট সিস্টেম। CLI দিয়ে ডেটা লেখা হয়, ড্যাশবোর্ড সেই ডেটা পড়ে দেখায়।
Owner: **mj-ahmad**

## ফোল্ডার কাঠামো

```
task-system/
├── run.sh            # একমাত্র এন্ট্রি পয়েন্ট
├── _lib.py           # সব ডেটা লেখা/পড়া, ID, টাইমস্ট্যাম্প, যাচাই
├── add_task.py       # নতুন টাস্ক
├── track_task.py     # ধাপ সম্পন্ন চিহ্নিত
├── complete_task.py  # টাস্ক সম্পন্ন ও আর্কাইভ রিপোর্ট
├── validate.py       # ডেটাবেস যাচাই
├── index.html        # ড্যাশবোর্ড (রেসপন্সিভ, ডেটা data.json থেকে)
├── data.json         # সব টাস্ক (DB)
├── registry.json     # ID কাউন্টার
├── attachments/      # সংযুক্ত ফাইল (TASK-ID নামে)
└── assets/
    └── logo.png      # আপনার লোগো এখানে রাখুন
```

## শুরু করুন

```bash
chmod +x run.sh
./run.sh init                 # প্রথমবার: ফোল্ডার ও ডেটা ফাইল তৈরি
./run.sh task "প্রকল্পের শিরোনাম" "তিন-চার লাইনের বিবরণ" --steps "ধাপ ১, ধাপ ২, ধাপ ৩"
./run.sh web                  # ড্যাশবোর্ড: http://127.0.0.1:8000
```

মোবাইল বা নেটওয়ার্কের অন্য ডিভাইসে দেখতে:

```bash
BIND=0.0.0.0 ./run.sh web
```

## কমান্ড

| কাজ | কমান্ড |
|---|---|
| নতুন টাস্ক | `./run.sh task "Heading" "Description" [--steps "a, b"] [--add-note "..."] [--add-file path]` |
| ধাপ সম্পন্ন | `./run.sh track TASK-000001 2` |
| টাস্ক সম্পন্ন | `./run.sh complete TASK-000001` (সব ধাপ শেষ হলে) |
| যাচাই | `./run.sh validate` |
| ড্যাশবোর্ড | `./run.sh web [port]` |

`--steps` কমা দিয়ে আলাদা করুন। `--add-note` ও `--add-file` একাধিকবার দেওয়া যায়।

## ID ও সময়

- **TASK ID** — `TASK-000001`, প্রতিটি টাস্কের স্বতন্ত্র নম্বর।
- **REG ID** — `REG-000001`, রেজিস্ট্রি নম্বর।
- ID-গুলো `registry.json` থেকে ক্রমানুসারে আসে। ব্যর্থ ইনপুটে কোনো ID নষ্ট হয় না।
- প্রতিটি সময় দুই ফরম্যাটে লেখা হয়: **ঢাকা (UTC+06:00)** ও **UTC**, `YYYY-MM-DD HH:MM:SS.mmm`।
- ধাপ সম্পন্ন, টাস্ক সম্পন্ন ও টাস্ক তৈরির সময় সবগুলোতে দুই টাইমস্ট্যাম্প থাকে এবং ইতিহাসে জমা হয়।

## ভাষা (EN | বাংলা)

ড্যাশবোর্ডের উপরের ডানদিকে **EN / বাংলা** টগল আছে। পছন্দ ব্রাউজারে মনে রাখা হয়, ডিফল্ট বাংলা।

দুই ধরনের লেখা আছে, এবং দুটির নিয়ম আলাদা:

1. **ইন্টারফেসের লেখা** (বাটন, লেবেল, হেল্প, ফুটার) `index.html`-এর `STRINGS` অবজেক্টে `bn` ও `en` দুই ভাষায় আছে। নতুন লেখা যোগ করতে একটি কী ও দুই ভাষার মান যোগ করুন, এবং HTML-এ `data-i18n="কী"` বসান।
2. **আপনার টাস্কের লেখা** (শিরোনাম, বিবরণ) ব্রাউজার অনুবাদ করে না। প্রতিটি টাস্কে আলাদা ঘর রাখুন:

```bash
./run.sh task "পরীক্ষা শিরোনাম" "বাংলা বিবরণ" \
  --heading-en "Test heading" --description-en "English description"
```

`data.json`-এ এগুলো `heading_en`, `heading_bn`, `description_en`, `description_bn` নামে সংরক্ষিত হয়। যে ভাষার ঘর খালি, সেখানে মূল `heading` ও `description` দেখানো হয়। তাই পুরনো টাস্ক ভাঙবে না।

## ডেটা নিরাপত্তা

- প্রতিটি লেখা অ্যাটমিক: প্রথমে অস্থায়ী ফাইলে লেখা হয়, তারপর নামটি বদলানো হয়। মাঝপথে বিদ্যুৎ গেলেও `data.json` নষ্ট হয় না।
- `complete` শুধু তখনই চলে যখন সব ধাপ শেষ।
- `validate` ডুপ্লিকেট ID, ভুল অগ্রগতি, অসম্পূর্ণ টাইমস্ট্যাম্প, হারানো সংযুক্তি ও কাউন্টারের অসংগতি ধরে।
- নিয়মিত ব্যাকআপ নিন: `cp data.json registry.json attachments -r ./backup/`

**একটি গুরুত্বপূর্ণ নিয়ম:** ডেটা বদলাতে শুধু CLI ব্যবহার করুন। `data.json` হাতে সম্পাদনা করলে `validate` চালিয়ে নিশ্চিত হন।

## প্রোডাকশনে প্রকাশ

`./run.sh web` একটি ডেভেলপমেন্ট সার্ভার। প্রকৃত ব্যবহারে এই ফোল্ডারটি Nginx, Caddy বা অন্য কোনো স্ট্যাটিক হোস্টিংয়ে দিন, এবং HTTPS ও পাসওয়ার্ড/অ্যাক্সেস কন্ট্রোল যোগ করুন। `data.json` ও `attachments/` সার্ভারে লেখার অনুমতি শুধু CLI-এর চালকের থাকা উচিত, ব্রাউজারের নয়। ড্যাশবোর্ড শুধু পড়ে, কিছু লেখে না।
